# 自动化测试说明

> 本文档说明 ThinkRAG 测试工程的目录结构、执行方式与 CI 配置。
> 对应手工用例表 `ThinkRAG测试用例.xlsx` 与缺陷报告 `ThinkRAG缺陷报告.xlsx`。

---

## 一、目录结构

```
ThinkRAG/
├── tests/                          pytest 用例
│   ├── conftest.py                 公共夹具：沙箱隔离、嵌入模型、附件
│   ├── helpers.py                  LLM 初始化、单次提问、拒答判定
│   ├── test_01_upload.py           文件格式支持矩阵（13 条）
│   ├── test_02_chunking.py         切块参数边界（7 条）
│   ├── test_03_consistency.py      数据一致性（5 条）
│   ├── test_04_qa.py               问答质量（15 条）
│   └── test_05_stability.py        连续 10 次稳定性（1 条，slow）
├── pytest.ini                      标记定义与 allure 输出配置
├── run_tests.bat                   本地一键执行
├── .github/workflows/qa-smoke.yml  CI 冒烟流水线
├── reports/
│   ├── allure-results/             allure 原始结果（json）
│   └── allure-report/              allure HTML 报告
└── 测试记录/
    ├── 测试数据/                   测试用固定文件（pdf/docx/xlsx/html/exe…）
    ├── 结果/                       每轮执行的 json 原始结果
    └── 证据/                       可读版证据与堆栈
```

## 二、执行方式

```bat
REM 只跑冒烟（不需要 API Key，用 MockEmbedding）
run_tests.bat smoke

REM 全量（跳过 slow），需要 config_store 里已配置 DeepSeek
run_tests.bat all

REM 连续 10 次稳定性
run_tests.bat stability

REM 打开 allure 报告
run_tests.bat report
```

等价的手工命令：

```bash
export PYTHONPATH="$PWD/.venv/Lib/site-packages"
export HF_ENDPOINT=https://hf-mirror.com
export PYTHONUTF8=1

# 冒烟
USE_MOCK_EMBED=1 .venv/Scripts/python.exe -m pytest -m "smoke and not llm"

# 全量
.venv/Scripts/python.exe -m pytest -m "not slow"
```

> `PYTHONPATH` 是必须的：本机 venv 会混入系统 Python 的 `Lib`，
> 不前置 venv 的 site-packages 会解析到系统安装的旧版 streamlit。

## 三、标记体系

| 标记 | 含义 | 是否进 CI | 说明 |
|---|---|---|---|
| `smoke` | 解析、切块、计数类 | ✅ | 不调用 LLM，秒级完成 |
| `llm` | 需要真实 LLM 的问答类 | ❌ | 需要 DeepSeek Key |
| `retrieval` | 依赖真实语义检索质量 | ❌ | MockEmbedding 下无意义 |
| `slow` | 耗时较长（10 次连续提问） | ❌ | 单独执行 |

组合执行的例子：

```bash
pytest -m "smoke and not llm"     # CI 口径
pytest -m "not slow"              # 全量口径
pytest -m "llm and not slow"      # 只跑问答
```

## 四、用例隔离怎么做的

原脚本是「每个场景起一个独立进程」，因为 ThinkRAG 的 `STORAGE_CONTEXT` 是模块级单例，
import 时就把 `storage/` 读进内存了，进程内清空磁盘无效。

pytest 版改为**每个用例一个独立的 `StorageContext` + 独立 `data` 目录**，
通过 `monkeypatch` 替换 `server.index` 模块里的两个绑定：

```python
ctx = StorageContext.from_defaults(
    docstore=SimpleDocumentStore(),
    index_store=SimpleIndexStore(),
    vector_store=SimpleVectorStore(),
)
ctx.persist_dir = str(storage_dir)
monkeypatch.setattr(index_mod, "STORAGE_CONTEXT", ctx)
monkeypatch.setattr(index_mod, "get_save_dir", lambda: str(data_dir))
```

效果：

- 隔离性和独立进程一样，但整个套件只加载一次嵌入模型（省 1.7s × 用例数）
- 跑测试**不会碰到**真实的 `storage/` 和 `data/`，本地知识库不会被破坏

## 五、xfail 与缺陷编号的对应

已知缺陷不写成"跳过"，而是 `xfail` + 缺陷编号，形成双向可追溯：
用例失败时报告里直接显示原因，缺陷修好之后该用例会变成 XPASS，提醒回归更新。

| 用例 | 对应缺陷 | 现象 |
|---|---|---|
| `test_xlsx_supported` | BUG-TRAG-008 | requirements 未声明 openpyxl，抛 ImportError |
| `test_pptx_supported` | BUG-TRAG-008 | 同上，缺 python-pptx |
| `test_html_strips_markup` | BUG-TRAG-014 | HTML 标签未剥离，源码入库 |
| `test_binary_file_rejected` | BUG-TRAG-013 | .exe 按纯文本读入 |
| `test_no_extension_rejected` | BUG-TRAG-013 | 无扩展名文件同样被读入 |
| `test_empty_file_produces_no_node` | BUG-TRAG-009 | 0 字节文件产生 1 个空节点 |
| `test_chunk_size_too_small` | BUG-TRAG-012 | chunk_size=1 抛底层 ValueError |
| `test_overlap_not_less_than_chunk` | BUG-TRAG-012 | overlap≥chunk 时内容膨胀 4.78 倍 |
| `test_duplicate_upload_does_not_grow` | BUG-TRAG-010 | 重复上传不去重，切块成倍增长 |
| `test_same_name_overwrite_effective` | BUG-TRAG-011 | 同名文件不覆盖，旧答案继续生效 |
| `test_query_after_all_deleted` | BUG-TRAG-002 | 空语料构建 BM25 抛 ValueError |

## 六、CI 配置

`.github/workflows/qa-smoke.yml`：push / PR 时自动跑 `smoke and not llm`，
用 `USE_MOCK_EMBED=1` 切到 MockEmbedding，避免在 runner 上下载 367MB 模型，
并把 `reports/allure-results` 作为制品上传。

### 已真跑通（不是配置好了待验证）

| 项 | 值 |
|---|---|
| 仓库 | `github.com/yan231ux/ThinkRAG`（fork 自 wzdavid/ThinkRAG） |
| 运行 | [#1](https://github.com/yan231ux/ThinkRAG/actions/runs/39379364541) |
| 结论 | **9 个步骤全部 success** |
| 环境 | ubuntu-latest / Python 3.11.17 / pytest 9.1.1 |
| 耗时 | 总 174 秒，其中依赖安装 139 秒、测试执行 **6 秒** |
| 结果 | `10 passed, 1 skipped, 20 deselected, 9 xfailed in 3.98s` |

完整日志见 `测试记录/证据/CI流水线运行记录.txt`。

**两个环境的结果差异是预期内的**：本地 10 xfailed（有 PPTX 样本），
CI 9 xfailed + 1 skipped（PPTX 样本 6.9MB 未入库，用例里加了 `skipif` 自动跳过）。

### 提交时踩到的坑

1. 原 `.gitignore` 里有 `test_*.*`，会把 `tests/` 全部忽略 → 已补 `!tests/**` 例外。
2. 含 API Key 的 `启动ThinkRAG.bat`、调试脚本 `probe_*.py`、超大样本
   （`大文件.txt` 2.5MB、`答辩演示.pptx` 6.9MB）都排除在版本库外，
   否则要么泄密要么拖慢 checkout。
3. 本机代理对 git 协议返回 502（`CONNECT tunnel failed`），但 GitHub API 可用，
   最终通过 Git Data API（blob → tree → commit → ref）完成推送。
   这只影响本机网络，别人正常 `git push` 即可。

```bash
# 正常环境下的推送方式
git remote add origin https://github.com/<你的用户名>/ThinkRAG.git
git add -A
git commit -m "test: 增加 pytest 用例体系与 CI 冒烟流水线"
git push origin main
```

## 八、覆盖率与并发（补充两项能力）

### 覆盖率

```bat
.venv\Scripts\python.exe -m pytest -m "not slow" ^
  --cov=server --cov=frontend --cov-report=term --cov-report=html:reports/htmlcov
```

| 口径 | 结果 |
|---|---|
| server 业务层 | **55%**（651 条语句） |
| 全仓含 frontend | 28%（frontend 644 条页面代码为 0%） |

**不要报整体 28%**——那会把 Streamlit 页面代码算进分母，反而显得测试很浅。
报 server 层 55%，并说明 UI 层由 Playwright 单独覆盖。

详细分模块数据与未覆盖原因见 `测试记录/覆盖率报告.md`。
本轮新增 `tests/test_06_core.py` 6 条用例，把 server 从 43% 提到 55%，
其中「索引重载」那条直接对应 BUG-TRAG-001 的触发路径。

### 并发压测

```bat
.venv\Scripts\python.exe 测试记录\concurrency_test.py
```

| 层 | 并发 8 时 | 结论 |
|---|---|---|
| 纯检索 | P50 129ms，56 QPS 饱和 | 2 并发即到吞吐上限，CPU/GIL 受限 |
| 端到端含 LLM | P50 1292ms，5.77 QPS，成功率 100% | 吞吐随并发线性增长，未饱和 |

关键对比：**检索只占端到端延迟的 2.4%**（1 并发 24ms / 984ms），
说明瓶颈在外部 LLM，不在本地机器。

详细数据、局限说明与面试口径见 `测试记录/并发压测报告.md`。

## 九、面试怎么讲（五句话）

1. **用例隔离**：原来每个场景起独立进程，改成每用例独立 `StorageContext`，
   跑完整套从 3 分钟降到 97 秒，而且不会污染本地知识库。
2. **缺陷可追溯**：12 条已知缺陷用 `xfail` 标注编号写进用例，
   CI 里是"预期失败"，缺陷修好后自动变 XPASS 提醒回归。
3. **CI 分层**：CI 只跑不依赖 LLM 的冒烟子集，用 MockEmbedding 把执行压到 4 秒，
   在 GitHub 托管 runner 上一次通过；问答质量这类需要真实模型的用例留在本地。
4. **覆盖率看口径**：server 业务层 55%，整体 28% 是因为把 644 行 Streamlit 页面
   算进了分母——那部分要用 Playwright 覆盖，不在 pytest 的范围。
5. **并发分层定位**：检索 56 QPS 饱和、端到端 8 并发 100% 成功，
   检索只占端到端 2.4% 延迟，瓶颈在外部模型而不是本地。
